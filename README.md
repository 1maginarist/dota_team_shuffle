# Dota Team Shuffle: Telegram-бот

Бот делит компанию друзей на две сбалансированные команды Dota 2 и раздаёт позиции с 1 по 5.

## Как этим пользоваться

**Игроки** один раз регистрируются в личке с ботом:

1. `/start` → прислать свой ММР числом, например `4500`.
2. Выбрать роли **по приоритету**: нажимать позиции от самой любимой. Роли, которые не выбрал, бот считает «не хочу».
3. После регистрации игрок **онлайн**, то есть виден организатору. Статус держится, пока игрок сам его не выключит: `/offline` (или кнопка в `/profile`). Включить обратно можно через `/online`.

**Организатор**:

1. Пишет `/game` в личке с ботом или в общем чате, если бот туда добавлен.
2. Видит список всех, кто онлайн. Сам организатор уже отмечен. Нажимает на игроков, чтобы отметить, кто играет. Кнопка «Показать всех» добавляет в список и оффлайн-игроков.
3. Нажимает **⚖️ Распределить**, и бот присылает составы:

```
🌞 Свет — Σ 22 900 · ср. 4 580
1️⃣ Керри — Артём · 3 300 ⭐
2️⃣ Мид — Гоша · 5 300 ⭐
3️⃣ Оффлейн — Петя · 4 000 ⭐
4️⃣ Семи-сап — Ваня · 3 900 (2-я)
5️⃣ Фулл-сап — Дима · 6 400 ⭐

🌚 Тьма — Σ 22 800 · ср. 4 560
...
⚖️ Разница: 100 ММР
🪑 Скамейка: Саша
```

4. Сразу после «Распределить» каждый участник, включая скамейку, получает в личку ту же общую расстановку, что видит организатор, с пометкой, за кого и на какой позиции он сейчас. **🔀 Другой вариант** показывает другое разбиение и обновляет эти же сообщения у всех без новых уведомлений. **✅ Утвердить** фиксирует состав: каждому приходит итоговая расстановка с уведомлением, а предварительное сообщение удаляется.

Сколько человек ни отметишь, бот разберётся:

- **9 человек**: команды 5 на 4, в меньшей одна позиция остаётся пустой.
- **Больше 10**: лишние идут на скамейку. Первыми садятся те, кто не сидел в прошлый раз, а среди равных те, кого отметили последними. Кто сидел на скамейке, в следующей утверждённой игре играет в приоритете.
- **Меньше 10**, например 3 на 3 или 4 на 4: тоже работает.

## Immortal Draft: капитаны выбирают игроков

Режим как в Dota 2: два капитана по очереди набирают себе команды.

1. Организатор пишет `/draft` (в общем чате или в личке с ботом) и отмечает **10 участников**: 2 капитанов и 8 игроков.
2. Выбирает двух капитанов. Можно вручную, а можно кнопкой «👑 Топ-2 по ММР»: так капитанов назначает сама Dota.
3. Жребий решает, кто из капитанов выбирает первым. Дальше пики идут по схеме **1-2-2-1-1-2-2-1**, как в Immortal Draft, и каждый капитан набирает по 4 игрока. Про каждого свободного игрока видно ник (и @username), ММР и роли по приоритету.
4. У каждого участника в личке живая доска драфта: видно, кто кого выбрал. Капитану, чей ход, приходит новое сообщение с кнопками и уведомлением. Поэтому драфт работает, даже если организатор запустил его у себя в личке. Если драфт идёт в общем чате, капитаны могут пикать и прямо там. Пикнуть не в свой ход нельзя. Организатор может пикнуть за капитана, который отошёл, и отменить последний пик.
5. Когда все разобраны, бот расставляет позиции внутри каждой команды по приоритетам ролей и показывает составы с разницей ММР. После «✅ Утвердить и разослать» каждый получает в личку свою команду и позицию.

## MVP вечера

После игр организатор присылает номера матчей:

```
/mvp 8123456789 8123456790 8123456791
```

Подойдут и ссылки на Dotabuff, OpenDota или Stratz. Бот загрузит статистику из OpenDota. У Dotabuff нет открытого API, а данные там те же. Если реплей ещё не разобран, бот сам отправит его на разбор и подождёт: обычно это занимает от 10 секунд до пары минут. В ответ придут MVP вечера со ссылками на Dotabuff и Steam, рейтинг всех игроков, лучший игрок каждого матча и разбор лидеров по составляющим.

**Чтобы бот различал игроков**, у всех в Dota должна быть включена «Общедоступная история матчей» (Expose Public Match Data). Иначе игрок останется анонимом и его матчи не склеятся.

### Лобби, которых нет в OpenDota: разбор реплея на сервере

Valve не отдаёт приватные лобби в публичное API, поэтому OpenDota их не видит. Для таких матчей бот разбирает реплей сам с помощью парсера OpenDota (`odota/parser`). Он поднимается вместе с ботом в `docker-compose.yml` и требует около 1 ГБ RAM во время разбора.

1. **Скачай реплей.** В клиенте Dota 2 открой профиль → «Недавние матчи» → нужный матч → «Загрузить» (Download Replay).
2. **Найди файл.** Он появится в папке `Steam\steamapps\common\dota 2 beta\game\dota\replays\` под именем `<номер матча>.dem`.
3. **Положи файл на сервер** в `data/replays/` рядом с ботом:
   ```bash
   scp 8123456789.dem root@<IP сервера>:~/dota_team_shuffle/data/replays/
   ```
   На Windows `scp` есть в PowerShell. Ещё можно воспользоваться WinSCP.
4. Отправь `/mvp 8123456789`. Если для матча есть файл в `data/replays/`, бот разберёт его (около 5–10 секунд), а остальные матчи загрузит из OpenDota как обычно.

Подходят `.dem`, `.dem.bz2` и `.dem.zst`. Имя файла начинается с номера матча. Разобранный результат сохраняется в `data/replays/parsed/`, поэтому повторный `/mvp` считается мгновенно. Статистика из реплея совпадает с OpenDota: K/D/A, варды, стаки, оглушения, участие в драках и позиции проверены на реальном матче.

**Как считается** (подробно — `/mvphelp`, код — `bot/mvp.py`):

1. **Метрики.** Фарм, опыт, добивания, убийства, помощь, урон, смерти, урон по строениям и лечение берутся как перцентиль OpenDota относительно всех игр на этом же герое. Варды, девард, стаки, оглушения, принятый от героев урон и участие в драках берутся как есть.
2. **Сравнение внутри позиции.** Каждая метрика сравнивается только с игроками той же позиции за вечер: пятёрка с пятёрками, керри с керри.
3. **Веса по ролям.** У керри важнее фарм и строения, у пятёрки — обзор и помощь, у оффлейна — контроль и танкование.
4. **Нормировка.** Балл матча ещё раз нормируется внутри позиции, и по среднему, и по разбросу. 50 означает средний уровень позиции, победа даёт ×1.1. Без этой нормировки MVP почти всегда доставался бы корам: у них баллы сильнее разбросаны. Я проверял на 34 реальных матчах. После нормировки MVP вечера распределился по позициям 1–5 как 3/3/2/1/2, а до неё во всех случаях MVP был кором.
5. **Итог вечера.** Это средний балл, к которому добавлены две «средние игры лобби». Одна удачная игра не перевешивает три стабильно сильные, а пропуск матча из-за скамейки стоит лишь несколько баллов.

**Вторая версия формулы** приходит третьим сообщением, чтобы результаты можно было сравнить. Это классические фэнтези-очки Valve с The International: 0.3 за убийство, 3 − 0.3 за каждую смерть, 0.003 за добивание и денай, 0.002 за единицу GPM, 1 за башню или Рошана, 3 × участие в драках, 0.5 за обсервер, 0.5 за стак, 0.25 за руну, 4 за первую кровь, 0.05 за секунду оглушения. Без поправки эта система почти всегда выбирает мидера: на 34 реальных матчах он оказался лучшим в 16 случаях из 34. Поэтому очки тоже сравниваются внутри позиции, а победа и итог вечера считаются так же, как в основной формуле.

## Как бот балансирует

Бот перебирает **все** разбиения на две команды (для 10 человек их 126). Внутри каждой команды он перебирает все раскладки по позициям (120 штук). Каждому варианту считается стоимость:

```
стоимость = |ΣММР Света − ΣММР Тьмы| + штрафы за роли
```

Штрафы считаются в «ММР-эквиваленте»:

| Игрок стоит на…           | Штраф |
|---------------------------|-------|
| своей 1-й роли            | 0     |
| 2-й по приоритету         | 100   |
| 3-й                       | 250   |
| 4-й                       | 400   |
| 5-й                       | 600   |
| роли, которую не выбирал  | 1500  |

Например, бот скорее согласится на лишние 100 ММР разницы, чем поставит человека на его вторую роль. Не на свою роль он ставит, только если иначе совсем никак. Перебор полный, поэтому найденный вариант действительно лучший по этой формуле. Веса настраиваются в `.env`.

## Запуск на VPS

Понадобятся Linux-сервер, `git` и Docker с плагином compose. Если Docker не установлен, поставь его командой `curl -fsSL https://get.docker.com | sh`.

1. В Telegram открой [@BotFather](https://t.me/BotFather), отправь `/newbot` и скопируй токен.
2. На сервере выполни:

   ```bash
   git clone https://github.com/1maginarist/dota_team_shuffle.git
   cd dota_team_shuffle
   cp .env.example .env
   nano .env                     # вписать BOT_TOKEN=...
   docker compose up -d --build
   docker compose logs -f        # убедиться, что бот запустился (Ctrl+C — выйти из логов)
   ```

3. Напиши боту `/start` и проверь, что он отвечает.
4. Если собирать игру должен только ты: напиши боту `/id`, впиши полученное число в `.env` как `ADMIN_IDS=123456789` и перезапусти бота командой `docker compose up -d`.
5. По желанию добавь бота в общий чат, чтобы делать `/game` там. Нажимать кнопки в меню сможет только тот, кто его открыл.

Бот работает через long polling, поэтому домен, HTTPS и открытые порты не нужны. Контейнер сам поднимается после перезагрузки сервера.

**Обновление:** `git pull && docker compose up -d --build`
**Бэкап:** вся база лежит в одном файле `data/bot.sqlite3`.

## Команды

| Команда            | Где          | Что делает                                         |
|--------------------|--------------|----------------------------------------------------|
| `/start`, `/profile` | личка      | регистрация / профиль с кнопками «Изменить»        |
| `/mmr 4500`        | личка        | поменять ММР (или просто прислать число)           |
| `/roles`           | личка        | заново выбрать роли                                |
| `/online`, `/offline` | везде     | показываться ли организатору                       |
| `/game`            | везде        | собрать игру (организатор)                         |
| `/draft`           | везде        | Immortal Draft: капитаны выбирают игроков (организатор) |
| `/players`         | везде        | все зарегистрированные игроки и их статус          |
| `/mvp id1 id2 id3` | везде       | MVP вечера по номерам матчей (организатор)         |
| `/mvphelp`         | везде        | как считается MVP                                  |
| `/id`              | везде        | свой Telegram ID для `ADMIN_IDS`                   |
| `/help`            | везде        | справка                                            |

## Настройки `.env`

| Переменная            | По умолчанию           | Зачем                                                    |
|-----------------------|------------------------|----------------------------------------------------------|
| `BOT_TOKEN`           | —                      | токен от @BotFather (обязательно)                        |
| `ADMIN_IDS`           | пусто (любой)          | кто может делать `/game`, ID через запятую               |
| `ROLE_PENALTIES`      | `0,100,250,400,600`    | штраф за 1-ю…5-ю роль из списка игрока                   |
| `OFF_ROLE_PENALTY`    | `1500`                 | штраф за роль, которую игрок не выбирал                  |
| `RESHUFFLE_TOLERANCE` | `200`                  | насколько «Другой вариант» может быть хуже лучшего       |
| `DB_PATH`             | `data/bot.sqlite3`     | где лежит база                                           |
| `OPENDOTA_API_KEY`    | пусто                  | ключ OpenDota, необязателен (без него ~2000 запросов/день) |

## Разработка

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
pytest                                  # тесты алгоритма + сквозной сценарий бота
BOT_TOKEN=... python -m bot             # запуск локально
```

Структура:

- `bot/balancer.py`: алгоритм балансировки, без зависимостей от Telegram
- `bot/handlers/profile.py`: регистрация, ММР, роли, онлайн/оффлайн
- `bot/handlers/organizer.py`: меню выбора игроков, распределение, утверждение и рассылка
- `bot/db.py`: хранилище SQLite
- `bot/captain_draft.py`: логика Immortal Draft; `bot/handlers/captains.py`: команда `/draft`
- `bot/mvp.py`: алгоритм MVP; `bot/opendota.py`: загрузка матчей и разбор реплеев; `bot/handlers/mvp.py`: команда `/mvp`
- `bot/texts.py`, `bot/keyboards.py`: тексты сообщений и кнопки
